# R6 — separately learned retrieval under an oracle-trained frozen reader

R5 is the first positive mechanism signal in this run: with validation-selected oracle-trained readout and O context, diagnostic event-description choices42/48 versus30/48 for matched address-shuffle training; strict recording success3/7 versus0/7, mixed-pattern1/4 versus0/4. Privileged endpoints and a fixed first-onset question family remain major limits. Do not report42/48 as deployable QA accuracy.

R6 tests whether it is possible to retain that readout while learning retrieval, instead of allowing joint optimization to absorb the language shortcut. Both conditions start from the same true-address oracle reader selected step400, and initialize only query/key/modality-key from R4 ordinary step200. Freeze content/time/memory/output reader parameters. Train only retrieval query/key/modality-key,1600 updates,seed20261017,AdamW lr.0003,wd.03,all four physical variants of one training recording per update. Alternate original source context and fixed O context. Server1 uses endpoint cross-entropy; server2 adds .5 binary-probability distillation from the same reader with true endpoint attention. There is no oracle attention at ordinary inference. Selection uses validation endpoint CE, recording averaged, includes step0. Read validation/diagnostic ordinary choices, endpoint localization, oracle, address shuffle and interchange separately.

This is a stagewise training baseline, not a novelty claim. Oracle knowledge occurs in training/diagnostic only. Generalization may fail because media-conditioned last-prompt query states provide poor semantic queries,31 recordings are small, and synthetic explicit event descriptions do not cover implicit narrated-event references. Passing the derived order set would still require natural QA and held-out recording/domain evaluation. No QA40 samples are used for optimization or model selection.
