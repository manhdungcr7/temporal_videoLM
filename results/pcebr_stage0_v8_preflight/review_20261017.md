# CLRV v8 — preflight review of the corrected source

Date: 2026-10-17

## Verdict

The newly supplied code is a genuine v8 source, and its normalized LF SHA-256 matches the hash announced in the attachment: `04304aade3bce851a26e6e20e7260139efc7e0f18a55c5ea59b2eb56f1696c84`. The earlier `audit.md` in this folder reviewed a stale v7 attachment and is superseded by this review.

The source includes the proposed v8 updates: log-space conditional normalization, a compatibility-sensitive dustbin term, a lexical-manifold gate, option-free-first rollout with a bridge score, and `DynamicCache` prefix reuse. I do not see the old v7-vs-v8 source mismatch in this attachment. I would still **not describe the method as general joint AV temporal reasoning or claim the null probability measures pair compatibility**: two implementation details contradict those claims. No v8 GPU experiment was run in this review.

## Material issues to resolve or narrow in the claims

### 1. The implementation is audio–visual only, despite claiming all four modality directions

The proposal/source docstring claims support for A→V, V→A, A→A and V→V (`stage0_pcebr_v8_candidate.py:1130–1134`). But the implementation always builds a cross-modal compatibility matrix from audio and visual banks: `man_omega = Z_A_c @ Z_V_c.T` and audio–visual coherence (`:1411–1413`). Query parsing only chooses which endpoint is more audio-dominant (`:1064–1077`, `:1299–1304`); it never chooses an A/A or V/V pair of banks. If no recognized relation connector is found, it assigns the same `content_or_deictic` rows to both endpoints (`:1056–1060`). The cue/connector lists are also finite and English-specific (`:1034–1047`, and constants near the top of file).

This is a substantive scope mismatch against the stated requirement for arbitrary user questions and all modality pairs. Either implement modality-pair-specific banks and a robust endpoint parser, or narrow the claim and evaluate only A↔V questions. A small list of relation words is not a general parser for implicit references, negation, multiple clauses, repeated entities, or unseen phrasings.

### 2. `excess_gate` is floored at 0.65, so the claimed wrong-query suppression cannot approach zero

At `:1405`, `excess_gate = max(0.65, gate_factorial[...])`. The unified gate itself can return zero (`:1104–1109`), but the value passed into slot metadata can never fall below 0.65. This directly contradicts the proposal’s mechanism claim that an unrelated content query yields near-zero gate and therefore prevents unsupported routing. The M0 algebraic gate check does not catch this downstream floor. Remove the floor or revise the stated mechanism, then test irrelevant, partially relevant, and absent-event questions on real clips while measuring both gate calibration and answer changes.

### 3. The dustbin score is sensitive to single-endpoint salience, not just pair compatibility

The code globally centers `pair_omega` (`:276–280`) and computes `expected_compat = p1ᵀ Ω p2`, then changes the dustbin potential using that scalar (`:296–298`). Global centering does not remove row/column effects under nonuniform marginals. For example, let `Ω_ij = a_i` (compatibility depends only on endpoint 1). After global centering, `p1ᵀΩp2 = Σ_i p1_i(a_i−mean(a))`, which is generally nonzero. Thus the null mass changes even though there is **no pair interaction** at all; the score reflects endpoint-1 salience. The same holds for column-only terms.

This is a concrete counterexample to interpreting `P_null` as evidence that the *pair* is incompatible. Use a weighted double-centered interaction residual under `p1,p2`, or demonstrate invariance to arbitrary additive row/column potentials. Add M0 controls for `Ω=a_i+b_j`, a true interaction, and permutations at fixed marginals. Until then, describe the quantity as a compatibility-conditioned heuristic null score, not a calibrated posterior probability of event absence.

### 4. The time axis is interpolated, not oracle physical time

The clock builder marks `is_uniform_grid_interpolation_not_frame_pts_oracle=True` (`:866`). It derives audio locations from RoPE/grid conventions and assigns video slots uniform grid midpoints (`:812+`). Consequently `lag`, synchronization, and temporal regime outputs are computed on an interpolated clock, not verified frame/audio presentation timestamps. The v7 report already documented cache/container/grid clock disagreements on the micro set. This does not make the method unusable, but “physical lag” or physical synchronization claims need timestamp validation or explicit qualification as grid-calibrated time.

### 5. The option-free prepass changes post-media positions

The option-free path keeps media-prefix tokens and selected stem/assistant rows (`:1698–1704`), then replaces all retained tail position IDs by a scalar monotonically increasing sequence (`:1705–1709`). It also drops other interstitial tokens by selecting `keep_indices`. Cache-vs-full parity on this transformed prompt verifies that implementation path, not parity with the processor’s original Qwen M-RoPE positions/control-token layout. Since Qwen2.5-Omni uses TMRoPE for synchronized multimodal positions, report this as an intentional prompt/position transformation and compare against native-preserved positions before attributing gains to the rollout bridge. See the [Qwen2.5-Omni technical report](https://arxiv.org/abs/2503.20215).

## Existing evidence that bears on the claims

There is **no v8 result yet**, so existing data cannot falsify v8’s performance. It does reject several stronger premises and shows what v8 must prove:

- The archived v7 micro8 run had native 5/8, CAOR-only 5/8 and v7 full 5/8, with zero rescued answers. Its joint branch had zero audio gate and zero Ψ on all eight samples. This is not a test of v8’s new gate, but it means v7’s proposed joint mechanism never demonstrated an end-to-end benefit. See [v7 report](../pcebr_stage0_v7/report.md).
- On the v7 two-hop roll suite, the full condition scored 57/156 (36.5%), no-Ψ scored 61/156 (39.1%), and matched 6-D Φ scored 58/156 (37.2%); the factorized/no-Sinkhorn control produced the same predictions as full. This argues against crediting v7’s 14-D/Sinkhorn design for an improvement. It does not disprove every joint-coupling design.
- The v7 semantic-wrong query gate was higher than the true-query gate (means 0.9640 vs 0.4032). That falsifies v7’s gate claim and makes the v8 gate worth testing, but v8’s 0.65 floor is inconsistent with the proposed near-zero rejection behavior.
- In the historical micro8 freeform run, sample 2150’s generated answer stated the correct “right after the speech” relation while its multiple-choice prediction was wrong. This supports testing an option-free rollout-to-choice bridge as a hypothesis; one sample does not show that the bridge generalizes. Evaluate against answer-order, option-only, relation-reversal, and independent semantic-judging controls. This is especially relevant given recent work on reasoning traces and test exploitation ([PMLR 2026](https://proceedings.mlr.press/v306/raman26a.html)).
- The premise that Qwen has no temporal information in its hidden states is too strong. Its technical report describes TMRoPE; failures of earlier interventions to change eight argmax outputs do not establish that temporal information is absent.

## What M0 can and cannot establish

M0 is useful for checking algebraic identities and constructed corner cases. It cannot establish event retrieval accuracy, calibration of `P_null`, robustness to arbitrary question forms, or temporal QA gains. The v8 report should keep these categories separate. A synthetic gate example with injected contamination does not establish real-query calibration; a synthetic lag counterexample does not establish correct clocks on real media.

## Suggested minimal pre-run changes

1. Fix the modality-pair mismatch or explicitly narrow the method to A↔V.
2. Resolve the `max(0.65, gate)` floor against the claimed null/rejection behavior.
3. Add row/column-gauge invariance tests for dustbin compatibility and rename `P_null` unless calibrated on held-out event-presence annotations.
4. Label temporal coordinates as grid-interpolated until validated against media timestamps; compare rebuilt vs native-preserved post-media positions.
5. Freeze all hand-set thresholds and query parsing before evaluating on a fresh, independently annotated set; include A→A/V→V, absent events, repeated events, and unseen question forms.

The current source is suitable for a controlled diagnostic run only after the claim/scope issues above are recorded. It is not yet evidence for broad task generality or CVPR-level novelty. A stronger benchmark and comparison against current temporal grounding work such as [TimeLens (CVPR 2026)](https://openaccess.thecvf.com/content/CVPR2026/html/Zhang_TimeLens_Rethinking_Video_Temporal_Grounding_with_Multimodal_LLMs_CVPR_2026_paper.html) are necessary for that assessment.
